# 가게 언어팩 만들기

**AI와 대화하면서, 우리 가게의 확인된 사실과 사장님의 말투를 담은 "언어팩"을 순서대로 만드는 템플릿입니다.**

> 설치하는 앱이 아닙니다. AI 대화창(ChatGPT, Claude 등)에 붙여넣어 쓰는 문서 묶음입니다.
> 검색 노출이나 매출을 보장하지 않습니다.

## 주소 하나로 시작하기

웹페이지를 읽을 수 있는 AI 대화창에 아래 주소를 보내세요.
AI가 시작 안내를 읽고 현재 자료를 확인한 뒤 필요한 것만 요청하도록 구성했습니다.

```text
https://github.com/jsk7767/owner-voice-langpack
```

**기존 언어팩에 사진만 추가하려면 이 주소를 보내세요.**

```text
https://github.com/jsk7767/owner-voice-langpack/tree/main/photo-pack
```

AI가 링크를 열지 못하면 [ZIP](https://github.com/jsk7767/owner-voice-langpack/archive/refs/heads/main.zip)을 받아
사진 작업에는 `photo-pack/PHOTO_PACK.md`를, 언어팩 신규 작성에는 `START.md`와
`template/00_MASTER.md`, `template/WRITING_POLICY.json`을 첨부하세요.
링크만으로 작업 의도를 인식하지 않는 AI에는 “이 팩으로 시작해 줘” 한 줄을 덧붙이면 됩니다.

### 이 주소를 받은 AI의 시작 순서

사용자가 이 팩을 쓰려는 맥락에서 주소를 전달했다면 저장소 소개만 요약하고 끝내지 말고 다음 단계로 진행한다.
사용자가 요약·검토·설명을 명시했다면 그 요청만 수행하며 설정을 시작하지 않는다.

1. 대화와 첨부 자료에서 기존 가게 언어팩, 사진, 글 또는 주제가 있는지 확인한다.
2. 사진팩 주소이거나 사진 선택·배치 요청이면 [사진 실행 지침](photo-pack/PHOTO_PACK.md)의 **0단계**를 읽고 시작한다.
3. 루트 주소만 있고 의도가 불명확하면 “기존 언어팩에 사진을 붙일까요, 가게 언어팩부터 만들까요?” 하나만 묻는다.
4. 신규 언어팩 작성이면 [START.md](START.md)와 템플릿 두 파일을 실제로 읽고, 이미 받은 자료를 재요청하지 않고 부족한 단계부터 진행한다.
5. 읽기 실패를 숨기지 않는다. 사진 지침 HTML이 열리지 않으면
   [원문](https://raw.githubusercontent.com/jsk7767/owner-voice-langpack/main/photo-pack/PHOTO_PACK.md)을 시도한다.
   웹 읽기 자체가 없으면 사용자가 첨부해야 할 파일을 정확히 알려 준다.

이 시작 안내는 AI의 도구·현재 사용자 지시 범위 안에서 적용한다.
주소 전달만으로 게시 권한이나 로컬 폴더 접근 권한이 생기지는 않는다.

**기존 언어팩을 이미 쓰고 있다면:** [가게 사진팩](photo-pack/README.md)을 추가하세요.
사진 폴더에서 실제 사진을 읽고 문맥에 맞는 선택·삽입 위치·업로드 확인을 안내하는 별도 묶음입니다.

| 하고 싶은 일 | 시작할 곳 |
|---|---|
| 내 가게 언어팩을 처음 만들기 | [빠른 시작](QUICK_START.md) |
| 기존 언어팩에 사진 선택·배치 기능 보강하기 | [가게 사진팩 사용 안내](photo-pack/README.md) |
| AI에게 사진 지침 바로 전달하기 | [PHOTO_PACK.md](photo-pack/PHOTO_PACK.md) |

사진팩은 `photo-pack/photos`에 가게 사진을 넣어 사용합니다.
[ZIP 다운로드](https://github.com/jsk7767/owner-voice-langpack/archive/refs/heads/main.zip) 후 `photo-pack` 폴더만 따로 전달해도 됩니다.
제작: **더장사 아카데미 승기 (전승기)**.

## 언어팩이 왜 필요한가요

AI에게 가게 글을 맡기면 보통 이런 일이 반복됩니다.

- 글을 쓸 때마다 메뉴, 가격, 영업시간, 주차를 다시 설명한다.
- AI가 **가게에 없는 메뉴**나 **있지도 않은 손님 이야기**를 지어낸다.
- 말투가 매번 달라서 "우리 가게 글" 같지 않다.
- 어느 순간 모든 글이 비슷한 구조로 시작하고 끝난다.

언어팩은 이 문제를 한 번에 정리해 두는 **가게 전용 기준 문서**입니다. 글을 쓸 때마다 언어팩을 AI에게 함께 주면, AI는 확인된 사실만 쓰고, 사장님이 정한 말투와 채널 규칙을 따르려고 합니다.

| 언어팩이 없을 때 | 언어팩이 있을 때 |
|---|---|
| 매번 가게 설명부터 다시 | 파일 두 개만 첨부 |
| 모르는 건 AI가 그럴듯하게 채움 | 모르는 건 "확인 필요"로 남김 |
| 글마다 말투가 들쭉날쭉 | 사장님이 고른 말투를 기준으로 |
| 채널 구분 없이 같은 글 복사 | 채널마다 맡는 역할이 다름 |

| 준비물 | 필수 | 설명 |
|---|---|---|

## 3단계로 시작하기

### ① 파일 받기

이 페이지 위쪽의 초록색 **`Code`** 버튼 → **`Download ZIP`** 을 눌러 받고 압축을 풉니다.

### ② AI에게 시작 요청문 붙여넣기

처음이라면 [`QUICK_START.md`](QUICK_START.md)의 요청문 하나를 복사해 붙여넣으세요.
AI가 GitHub 파일을 열지 못한다고 하면 아래 세 파일을 첨부합니다.

1. `START.md`
2. `template/00_MASTER.md`
3. `template/WRITING_POLICY.json`

> 파일 이름만 적는다고 AI가 내용을 읽지는 못합니다. 실제 파일을 첨부하거나 내용을 붙여넣어야 합니다.
> 전체 설정 순서와 세부 규칙은 [`START.md`](START.md)에 있습니다.

### ③ AI의 질문에 하나씩 답하기

AI가 "가게 자료를 주세요"라고 시작합니다. 있는 자료를 주면 AI가 먼저 정리해서 보여주고, 사장님은 **틀린 것만 고치면** 됩니다.

## AI가 묻는 순서 — 단계별 자세히

긴 설문을 한꺼번에 채우지 않습니다. **첫 글을 함께 만들면서 부족한 것만 묻는** 방식입니다.

### 1단계 · 자료 받기
- **AI가 하는 일:** 플레이스 주소, 메뉴판 사진, 소개 글, 예전 글을 받습니다. 같은 이름의 다른 지점과 헷갈리지 않게 주소를 확인합니다.
- **사장님이 할 일:** 있는 자료만 주세요. 자료가 없으면 짧게 말로 설명해도 됩니다.

### 2단계 · 가게 사실 정리
- **AI가 하는 일:** 메뉴·가격·주소·영업시간·주차·예약 방법을 표로 정리합니다. 줄마다 **출처**와 **사장님 확인/미확인**을 표시합니다.
- **사장님이 할 일:** 틀린 것, 바뀐 것만 고칩니다.
- **왜 중요한가:** 인터넷 정보는 오래된 경우가 많습니다. 가격이 자료끼리 다르면 AI는 조용히 고르지 않고 사장님께 묻습니다.

### 3단계 · 사장님의 생각과 경험 (선택)
- **AI가 하는 일:** "브랜드 철학"처럼 어렵게 묻지 않고, 쉬운 질문을 하나씩 합니다.
  - 손님이 가게를 나가면서 어떤 말을 해주면 좋겠어요?
  - 장사하면서 이것만큼은 지키려고 하는 게 있나요?
  - 가게를 하면서 기억에 남는 일이 있나요? (글에 써도 되는 것만)
- **사장님이 할 일:** 답하기 싫거나 공개하기 싫은 것은 건너뛰세요.
- **왜 중요한가:** 사장님이 실제로 겪은 일만 1인칭으로 쓸 수 있습니다. 여기서 확인된 경험이 없으면 AI는 경험담을 쓰지 않습니다.

### 4단계 · 고객
- **AI가 하는 일:** 지금 자주 오는 손님과, 앞으로 늘리고 싶은 손님을 따로 묻습니다. 그 손님들이 알고 싶어 할 것(위치, 주차, 단체석, 아이 동반 등)을 정리합니다.

### 5단계 · 말투
- **AI가 하는 일:**
  1. 사장님이 직접 쓴 글이 있으면 호흡(문장 길이, 줄바꿈, 끝맺음)을 정리합니다.
  2. 좋아하는 다른 사람의 글이 있으면 [문체 카드를 만들어 호흡을 따라 씁니다](#좋아하는-글쓴이의-문투-따라-쓰기)합니다.
  3. 같은 내용을 두세 가지 말투로 짧게 써서 보여줍니다.
  4. 쓰지 않을 단어, 호칭(직원을 부르는 말 등), 느낌표·이모지·해시태그 사용 여부를 묻습니다.
- **사장님이 할 일:** 마음에 드는 말투를 고르고, 싫은 표현을 알려 주세요. 고른 말투는 나중에 바꿀 수 있습니다.
- **결과:** 쓰지 않기로 한 표현은 `WRITING_POLICY.json`의 금칙 목록에 들어갑니다.

### 6단계 · 채널
- **AI가 하는 일:** 글을 올릴 채널을 고르고, 채널마다 맡는 일을 정합니다.

  | 채널 예시 | 맡을 수 있는 일 |
  |---|---|
  | 스레드 | 한 순간과 대화를 여는 질문 |
  | 네이버 블로그 | 방문을 판단하는 데 필요한 정보 (위치·동선·자리) |
  | 티스토리 | 검색한 사람이 다시 찾지 않아도 되는 상세 설명 |
  | 인스타그램 | 사진 중심의 짧은 소개 |

- **사장님이 할 일:** 실제로 쓸 채널만 고르세요. 채널마다 태그를 쓸지, 사진은 누가 올릴지도 정합니다.

### 7단계 · 사진 권리
- **AI가 하는 일:** 사진을 한 장씩 설명하게 하지 않고, 묶음으로 받아 **직접 촬영 / 사용 허락 있음 / 권한 모름**으로 나눕니다. 얼굴·연락처·화면이 보이는 사진은 따로 확인합니다.
- **규칙:** 권한을 모르는 사진은 게시 보류입니다. 인터넷에 공개된 사진이라고 마음대로 써도 되는 것은 아닙니다.

### 8단계 · 게시 권한
- **기본값은 "초안까지만"** 입니다. AI에게 실제 게시까지 맡길지는 따로 정하고, 대상 채널과 범위를 적습니다.
- 비밀번호나 로그인 정보는 언어팩에 적지 않습니다.

### 9단계 · 첫 글 같이 만들기
- **AI가 하는 일:** 정리한 내용으로 첫 초안을 씁니다. 쓰기 전에 "이번 글의 재료"(장면, 숫자, 손님이 실제로 한 질문, 운영 기록, 사장님 생각)를 먼저 적고, **가장 강한 재료로 글을 시작합니다.**
- **사장님이 할 일:** 고칠 곳을 말하세요. AI가 "이건 앞으로도 지킬 규칙으로 저장할까요?"라고 물으면, 계속 지킬 것만 허락하세요. 이번 글에만 해당하는 수정은 규칙이 되지 않습니다.

### 10단계 · 저장
- **AI가 하는 일:** 채운 `00_MASTER.md`와 `WRITING_POLICY.json`을 보여주고, 아직 비어 있는 칸 목록을 따로 알려 줍니다. 빈칸이 남아 있으면 "설정 완료"라고 하지 않습니다.
- **사장님이 할 일:** 두 파일을 내 컴퓨터의 한 폴더에 저장하세요. 그 폴더가 **내 가게 언어팩**입니다.

## 대화는 이런 식으로 흘러갑니다 (예시)

아래는 **가상의 동네 빵집**으로 만든 예시입니다. 실제 가게 정보가 아닙니다.

```text
AI    가게 자료를 주세요. 네이버 플레이스 주소나 가게 이름·지역, 메뉴판 사진이 있으면 좋아요.
사장님 (플레이스 주소와 메뉴판 사진 첨부)

AI    자료에서 정리한 내용이에요. 틀린 곳만 알려 주세요.
      | 항목      | 내용             | 출처        | 확인   |
      | 소금빵    | 3,000원          | 메뉴판 사진 | 미확인 |
      | 영업시간  | 08:00~19:00      | 플레이스    | 미확인 |
      | 주차      | 자료에 없음      | -           | 미확인 |
사장님 소금빵은 이번 달부터 3,200원이고, 주차는 가게 앞 2대 가능해요.

AI    반영했어요. 다음 질문이에요.
      손님이 가게를 나가면서 어떤 말을 해주면 좋겠어요?
사장님 "빵이 아직 따뜻하네요" 정도요.

AI    같은 내용을 세 가지 말투로 써 봤어요. 어느 쪽이 가까운가요?
      ① 오늘 첫 소금빵이 나왔어요. 아직 따뜻합니다.
```

## 완성한 언어팩 저장하고 다시 쓰기

대화가 끝나면 언어팩을 **파일로** 저장해야 다음에 다시 쓸 수 있습니다.

### 파일로 받는 방법

- **AI에게 파일로 달라고 하세요.**
  ```text
  완성한 00_MASTER.md와 WRITING_POLICY.json을 내려받을 수 있는 파일로 만들어줘.
  ```
  파일 만들기를 지원하는 AI는 내려받기 링크를 줍니다.
- **파일로 안 된다면 복사해서 저장하세요.**
  1. AI에게 "00_MASTER.md 전체를 코드 상자 하나에 담아서 보여줘"라고 요청합니다.
  2. 상자 오른쪽 위의 복사 버튼을 누릅니다.
  3. 메모장을 열어 붙여넣고, `다른 이름으로 저장` → 파일 이름 `00_MASTER.md`, 인코딩 `UTF-8`로 저장합니다.
  4. `WRITING_POLICY.json`도 같은 방법으로 저장합니다.
- 두 파일을 **한 폴더**(예: `내가게-언어팩`)에 넣어 두세요.

**저장한 뒤 확인할 것**
- 파일 이름이 정확히 `00_MASTER.md`, `WRITING_POLICY.json`인지 (메모장이 뒤에 `.txt`를 붙이지 않았는지)
- `WRITING_POLICY.json`을 AI에 다시 첨부해 "JSON 형식 오류가 없는지 확인해줘"라고 한 번 요청하기
- 두 파일이 같은 폴더에 있는지

### 매번 첨부하지 않는 방법 — 프로젝트 기능

ChatGPT와 Claude에는 **프로젝트** 기능이 있습니다. 프로젝트에 파일을 한 번 올려 두면, 그 프로젝트 안의 모든 대화에서 AI가 파일을 참고합니다.

1. 새 프로젝트를 만들고 이름을 가게 이름으로 정합니다.
2. 프로젝트 파일(지식)에 `00_MASTER.md`, `WRITING_POLICY.json`, `CHANNELS.md`, `STYLE_REFERENCE.md`를 올립니다.
3. 프로젝트 안에서 새 대화를 열고 `template/PROMPTS.md`의 요청문으로 글을 요청합니다.

> 메뉴 이름과 위치는 서비스 업데이트에 따라 바뀔 수 있습니다. 프로젝트 기능이 없는 요금제라면 대화마다 파일을 첨부하세요.

### 가게 정보가 바뀌면

언어팩 파일을 고친 뒤 **프로젝트에 올린 파일도 새 파일로 바꿔** 두세요. 예전 파일이 남아 있으면 AI가 옛 가격으로 쓸 수 있습니다.

### BrowserOS Neo와 Aside에서 쓰기

Neo나 Aside에 GitHub 페이지를 열어 두는 것만으로 언어팩이 자동 적용되지는 않습니다.
AI가 `00_MASTER.md`와 `WRITING_POLICY.json`을 실제로 읽었는지 확인해야 합니다.
처음 만들기, 저장, 새 대화에서 다시 쓰는 순서는 [`BROWSERS.md`](BROWSERS.md)에 정리했습니다.

## 좋아하는 글쓴이의 문투 따라 쓰기

"이 사람처럼 쓰고 싶다"는 글이 있다면, 문장을 베끼지 않고 **호흡과 리듬만** 따라 씁니다. 말끝(-다/-요)은 내 말투를 정했다면 내 것을 지킵니다.

```
① 문체 카드 만들기   그 사람의 글 5~20편 → 문장 길이·리듬·말끝·줄바꿈·연결어를 한 장으로 정리
② 문체 카드대로 쓰기  내 가게 재료로, 카드의 호흡만 빌려 초안 작성
③ 비교하고 고치기    초안과 참고 글을 숫자로 비교 → 차이 나는 곳만 고침
                     + 참고 글과 똑같은 문장이 없는지 검사
```

| 따라 해도 되는 것 | 따라 하면 안 되는 것 |
|---|---|
| 문장 길이, 끊는 호흡, 줄바꿈 습관, 연결어 빈도, 시작·끝 내는 방식 (말끝은 내 말투를 안 정했을 때만) | 참고 글의 문장, 표현 묶음, 그 사람이 겪은 일, 그 사람인 척하기 |

AI 대화창만으로도 할 수 있고, 파이썬을 쓸 수 있다면 도구가 더 정확하게 셉니다.

```bash
python tools/style_profile.py 참고글.txt                       # ① 문체 카드용 수치
python tools/style_profile.py 참고글.txt --compare 내초안.txt  # ③ 비교 + 베낀 구간 검사
python tools/style_profile.py 참고글.txt --compare 내초안.txt --keep-draft-ending  # 내 말끝(해요체 등)은 유지
```

비교 결과는 이렇게 나옵니다.

```text
== 조정 제안 ==
- 문장 평균 길이: 참고 38.8 / 초안 16.4 → 문장이 참고 글보다 짧습니다. 짧은 문장 몇 개를 이어 보세요. 이번에는 27.6 정도까지만 옮겨 보세요.
- 한 줄에 한 문장 비율(%): 참고 30.3 / 초안 90.9 → 줄바꿈이 참고 글보다 잦습니다. 이번에는 60.6 정도까지만 옮겨 보세요.
- 한 번에 다 맞추지 말고 차이의 절반만 고친 뒤 다시 비교하세요. 문체를 고친 뒤에는 새로 생긴 사실이 없는지도 확인하세요.

== 베낀 구간 검사 (공백 빼고 12자 이상 똑같은 부분) ==
- 없음
```

단계별 요청문과 자세한 방법은 [`STYLE_REFERENCE.md`](STYLE_REFERENCE.md)에 있습니다.

## 스레드·네이버 블로그·티스토리 글 쓰기

새 AI 대화(또는 프로젝트)에서 내 `00_MASTER.md`, `WRITING_POLICY.json`과 [`CHANNELS.md`](CHANNELS.md)를 첨부한 뒤 [`template/PROMPTS.md`](template/PROMPTS.md)의 요청문을 쓰면 됩니다.

채널마다 맡는 일이 다릅니다. 같은 재료로 쓰되 문장을 옮겨 적지 않습니다.

| 채널 | 맡는 일 | 핵심 규칙 (자세한 것은 `CHANNELS.md`) |
|---|---|---|
| 스레드 | 한 순간과 대화 | 한 편만 읽어도 완결, 60자 미만은 피하기, 좁은 질문 검토, 공지만 담은 글 피하기 |
| 네이버 블로그 | 방문을 판단할 정보 | 가게 소개 문장으로 매번 시작하지 않기, 소제목 서너 개, `1.` 대신 `1)`, 사진은 한 장씩, 장소 카드 |
| 티스토리 | 다시 찾지 않아도 되는 상세 설명 | 검색한 질문에 끝까지 답하기, 네이버 글 옮기지 않기, 발행 전 공개 설정 확인 |

`PROMPTS.md`에는 채널별 요청문과, **같은 재료로 세 채널을 한 번에** 쓰는 요청문이 들어 있습니다.

**지시를 안 지키거나 같은 이야기를 반복한다면:** [실행 스킬 `SKILL.md`](SKILL.md)를 함께 읽게 하세요. `실제로 읽은 자료 → 적용 기준 최대 5개 → 최근 글의 주장·사례·결말 비교 → 초안 → 근거별 검수` 순서로 작업합니다. 지적받으면 사과만 하지 않고 `어긴 기준 → 실제 수정 부분 → 재확인 결과`를 제출합니다. 과거 글이 없으면 비교 불가로 남기며, 새 사실을 만들어 차이를 채우지 않습니다.

스킬 기능을 지원하는 도구에서는 해당 도구의 스킬 폴더 아래 `owner-voice-langpack/SKILL.md`와 `owner-voice-langpack/tools/repetition_check.py`를 함께 둡니다. 자동 로딩 방식은 도구마다 다르므로 설치만으로 적용됐다고 판단하지 않습니다. 일반 대화창에서는 파일을 첨부하거나 전문을 붙여넣으면 됩니다. 완성할 내 가게 언어팩은 기존처럼 `00_MASTER.md`와 `WRITING_POLICY.json` 두 파일이며, 스킬과 도구는 작업 보조입니다.

**반복을 실제로 검사하기:** [반복 검사 도구](tools/repetition_check.py)는 추가 패키지 없이 Python 3.10 이상에서 실행합니다. 본문 파일과 비교할 승인 글 폴더를 준비해 `python tools/repetition_check.py body.txt --history-dir approved_history --json`으로 검사합니다. 이력 폴더가 없으면 해당 옵션을 생략합니다. 허용된 표현만 `--allow-term "상호명"`으로 지정합니다. 같은 글 안의 반복과 과거 글과의 겹침이 원문 줄·횟수·출처와 함께 나옵니다.

Windows에서는 `python` 대신 `py -3`를 사용하세요. 이 명령은 받은 저장소 또는 설치한 스킬의 폴더에서 실행하며, 다른 위치라면 스크립트의 실제 경로를 지정합니다.

기본 후보는 정규화 문장/행 2회, 표면형 단어 4회, 2~8어절·합계 6문자 이상 어구 3회입니다. 과거 글 어구는 4~12어절·합계 12문자 이상을 비교합니다. 문서당 50,000토큰을 넘으면 입력 오류입니다. 조사·어미 변화와 의미 반복은 자동 판정하지 않습니다. 종료 코드 0은 분석 완료, 2는 입력 오류이며 후보가 없어도 사실·의미 검토는 남습니다. `history.status=absent/empty`를 과거 글 비교 통과로 해석하지 마세요.

반복 후보를 **삭제·통합·근거 있는 구체화**로 다듬고 같은 조건으로 재검사합니다. 필요한 상호·메뉴명은 유지하며 동의어 치환이나 사실 창작으로 경고만 없애지 않습니다. 참고한 한국어 분석·유사도·평가 프로젝트와 적용 경계는 [REFERENCES.md](REFERENCES.md)에 정리했습니다.

### 자동 검사와 사람 확인의 경계

| 도구 | 자동으로 확인하는 것 | 확인하지 못하는 것 |
|---|---|---|
| `style_profile.py` | 문장 길이·말끝·줄바꿈 등 관찰값, 참고 글과 같은 구간 | 사실 여부, 자연스러움 합격, 그 사람다운지 여부 |
| `repetition_check.py` | 같은 글과 과거 글의 표면 반복 후보 | 의미가 같은 이야기, 반복이 필요한지 여부 |
| `editor_blocks_check.py` | 승인한 필수 편집 블록의 표시·개수·필수 정보 | 실제 편집기 모양, PC·모바일 표시 |

`WRITING_POLICY.json`의 금칙, 채널별 개수 제한, 사실·경험·사진 권리·게시 권한은
현재 도구 전체가 자동 검사하지 않습니다. AI와 사람이 원고를 대조해야 합니다.
종료 코드 0은 해당 도구의 분석이 끝났다는 뜻이지 글 전체가 통과했다는 뜻이 아닙니다.

**블로그 편집도 언어팩에 담습니다.** 실제 매장 슬로건 인용구, 접힌 모서리 목차, 세로선 소제목, 가운데 정렬 매장 안내처럼 역할을 나눠 선택합니다. 매 글 같은 순서로 강제하거나 다른 가게의 정보를 복사하지 않습니다. [편집 지침](CHANNELS.md#블로그-편집-디테일)을 참고해 `00_MASTER.md`의 "블로그 편집 선호"를 채우고, `PROMPTS.md`의 "기존 블로그의 편집만 다듬기" 요청문을 쓰세요. 이모지는 사장님이 허용한 범위만 적용합니다.

| 요청 | 언제 쓰나 | 결과 |
|---|---|---|
| **채널별 작성** | 스레드·네이버·티스토리 초안이 필요할 때 | 이번 글의 재료 정리 → 가장 강한 재료로 시작한 초안 → 확인 질문 |
| **검수** | 올리기 전 점검 | 사실·경험·사진 권리·금칙·반복을 나눠 본 점검표 |
| **승인 기록** | 마음에 든 본문을 기준으로 남길 때 | 승인한 본문과 선택 이유 기록 (게시는 따로) |

**작성 요청 예시**

```text
첨부한 내 언어팩을 먼저 읽어줘.
주제: 비 오는 날 아침에 첫 빵이 나오는 시간
채널: 스레드
범위: 초안만 작성해. 게시하지 마.
확인된 사실과 내가 실제로 겪은 일만 써줘. 모르는 건 끝에 확인 필요로 모아줘.
```

**올리기 전에 직접 확인할 것**

- [ ] 가격·시간·메뉴가 지금 사실과 같은가
- [ ] 내가 겪지 않은 일이 들어가지 않았는가
- [ ] 쓰기로 한 사진의 권리를 확인했는가
- [ ] 최근 글과 첫 문장·끝맺음이 똑같지 않은가
- [ ] 네이버 블로그라면 첫 문단이 제목 검색어에 확인된 사실로 답하는가
- [ ] 네이버 블로그 사진은 서로 다른 장면 5~10장이고 대표 사진이 첫 번째인가

| 일회 요청과 상시 규칙 | 이번 글에만 해당하는 요청과 계속 지킬 규칙을 구분 |

| 검수와 공개 승인 | 초안 승인과 공개 승인, 공개 결과 확인을 따로 기록 |

### `template/WRITING_POLICY.json` — 자동 검사 설정

사람이 읽기보다 검사 도구가 읽는 파일입니다. AI가 5단계에서 금칙을 채웁니다.

| 항목 | 뜻 |
|---|---|
| `pack_id` | 내 가게를 뜻하는 영문 소문자 ID (예: `my-bakery`) |
| `rules.banned` | 쓰지 않기로 한 표현 목록 |
| `preferences` | 선호하는 분량과 말투 메모 (강제 아님) |
| `channels` | 채널별 제한과 발행 전 점검 기준. 스레드 500자는 기존 도구 설정값이며 최신 제한으로 확인된 값이 아닙니다 |
| `channels.blog.serp_card` | 네이버 블로그 첫 문단 답과 사진 계획의 초기 기준. 사진 5~10장·8~10장 목표는 권리 확인과 장면 다양성을 전제로 하며, 10장은 관찰값이지 공식 보장이 아닙니다 |
| `repetition` | 과거 글과 문장·어구가 얼마나 겹치면 경고할지 |

### `template/PROMPTS.md` — 요청문 모음

작성·검수·승인 기록 요청문이 들어 있습니다. 복사해서 쓰면 됩니다.

## 이 언어팩이 지키는 원칙

1. **확인된 사실만 씁니다.** 모르는 가격·날짜·메뉴는 비워 두고 "확인 필요"로 남깁니다.
2. **겪지 않은 일을 만들지 않습니다.** 사장님이 실제로 겪은 일만 1인칭으로 씁니다. 손님 말도 실제 들은 것만 씁니다.
3. **같은 구조를 반복하지 않습니다.** 매번 같은 틀로 쓰면 독자는 기계가 찍어낸 글로 느낍니다. 그날의 재료가 글의 시작과 구조를 정합니다.
4. **사람처럼 보이려고 꾸미지 않습니다.** 일부러 오타를 넣거나 문장 길이를 흔들지 않습니다. 독자가 실제로 걸리는 것은 반복, 사실 오류, 구체성 없는 칭찬입니다.
5. **채널마다 새 가치를 줍니다.** 같은 재료를 써도 문장을 옮겨 적지 않습니다.
6. **초안과 게시는 다릅니다.** 기본은 초안까지이고, 실제 게시는 사장님이 따로 허락합니다.
7. **한 번의 수정이 영원한 규칙이 되지 않습니다.** 계속 지킬 것만 사장님 허락을 받아 저장합니다.

## 자주 묻는 질문

**Q. 컴퓨터를 잘 못 다뤄도 쓸 수 있나요?**
A. 네. 파일을 받아 AI 대화창에 붙여넣고 질문에 답하면 됩니다. 프로그램 설치나 명령어 입력은 필요 없습니다. `tools` 폴더는 파이썬을 쓰는 분만을 위한 선택 사항입니다. 다만 AI 대화창에서 센 문체 수치는 **수동 추정**이라 대략적인 값입니다. 정확히 재고 싶을 때만 도구를 쓰세요.

**Q. 모든 칸을 다 채워야 하나요?**
A. 아니요. 첫 글의 가게 식별 정보, 이번 사실, 말투, 채널·주제가 확인되면 **첫 글 작성 준비 완료**로 구분할 수 있습니다. 나머지는 "나중에"로 넘기고 `미입력` 목록에 남깁니다. `미입력`을 설정 완료나 확인된 사실로 바꾸지는 않습니다.

**Q. 어떤 AI를 써야 하나요?**
A. 파일 첨부가 되는 AI 대화창이면 됩니다. 다만 같은 언어팩을 줘도 AI마다 결과가 조금씩 다르고, 틀린 내용을 쓸 수도 있습니다. 올리기 전에 꼭 읽어 보세요.

**Q. 가게 정보가 바뀌면요?**
A. 언어팩의 "확인된 사실" 표를 고치세요. AI는 바뀐 가격이나 영업시간을 스스로 알 수 없습니다. 오늘만 바뀐 정보(예: 오늘만 일찍 닫음)는 언어팩이 아니라 그날 요청에 적으세요.

**Q. 좋아하는 작가처럼 써 달라고 해도 되나요?**
A. 문장 길이나 호흡 같은 특징을 참고하는 것은 괜찮습니다. 그 사람의 문장을 그대로 쓰거나, 그 사람이 겪은 일을 내 경험처럼 쓰는 것은 안 됩니다.

**Q. 여러 채널을 한 번에 쓸 수 있나요?**
A. 네. 같은 재료로 채널마다 따로 쓰되, 문장을 복사하지 말고 채널별 역할에 맞게 다시 쓰도록 요청하세요.

**Q. 여러 매장을 운영하면요?**
A. 매장마다 언어팩 폴더를 따로 만드세요. 한 매장의 사실·사진·게시 권한이 다른 매장 글에 섞이면 안 됩니다.
