# 가게 사진팩

**사진은 폴더째 주세요. AI가 글에 맞는 사진과 넣을 위치를 고르도록 돕습니다.**

제작: 더장사 아카데미 승기 (전승기)

## 이 주소만 AI에게 보내세요

```text
https://github.com/jsk7767/owner-voice-langpack/tree/main/photo-pack
```

AI가 아래 시작 지침을 읽고, 이미 있는 언어팩·사진·초안을 확인한 뒤 부족한 것만 요청합니다.
대표님이 설정 순서를 외우거나 사진별 분류표를 만들 필요는 없습니다.
웹 읽기가 없는 AI에는 [PHOTO_PACK.md](PHOTO_PACK.md)를 첨부하세요.
링크를 소개만 하는 AI에는 “이 사진팩으로 시작해 줘”라고 덧붙이세요.

### 이 주소를 받은 AI에게

사용자가 사진팩을 사용하려고 이 주소를 보냈다면 설명만 하고 끝내지 않는다.
요약·검토 요청이 명시되어 있으면 해당 요청을 우선한다.

1. [PHOTO_PACK.md](PHOTO_PACK.md)를 실제로 열어 **0. 주소로 시작할 때**를 따른다.
   HTML 파일 읽기가 실패하면 [원문 주소](https://raw.githubusercontent.com/jsk7767/owner-voice-langpack/main/photo-pack/PHOTO_PACK.md)를 사용한다.
2. 현재 대화·첨부에서 확인한 것부터 재사용한다. 언어팩을 처음부터 다시 만들지 않는다.
3. 자료가 모두 준비됐으면 사진 열람과 배치 작업을 시작한다. 부족하면 지금 필요한 요청 하나만 한다.
4. 다른 파일을 열 수 없더라도 이 안내를 읽었다면 다음과 같이 진행한다:
   실제 사진을 읽을 수 있는지 확인하고, 실행 지침 원문을 첨부해 달라고 요청한다.
   파일을 읽기 전에는 읽었다고 말하거나 완료를 선언하지 않는다.

일반적인 첫 응답 예시(사진이 아직 없을 때):

> 사진팩을 읽었습니다. 먼저 가게 사진 폴더나 ZIP을 보내 주세요.
> 사진별 설명은 제가 정리하겠습니다.

사진과 초안이 이미 있으면 위 요청을 반복하지 말고 바로 열람한다.
웹을 전혀 읽지 못하는 AI는 이 시작 안내도 볼 수 없으므로 파일 첨부 방식이 필요하다.

이미 만든 가게 언어팩에 추가하는 문서입니다. 별도 앱이나 자동 업로드 프로그램이 아닙니다.
대표님께 전달할 때는 이 `photo-pack` 폴더 전체를 압축해서 드리면 됩니다.
매장별 실제 사진과 사용 기록은 공개 GitHub에 올리지 않고 각 대표님 컴퓨터에 보관합니다.

## 사진팩 받기

1. [전체 파일 ZIP 받기](https://github.com/jsk7767/owner-voice-langpack/archive/refs/heads/main.zip)를 눌러 압축을 풉니다.
2. 압축을 푼 폴더에서 **`photo-pack`만 사용**하세요. 기존 언어팩을 새로 만들 필요는 없습니다.
3. 안내만 먼저 보려면 이 페이지를 읽고, AI 지침은 [PHOTO_PACK.md](PHOTO_PACK.md)를 사용하세요.

사진팩에는 실제 가게 사진이 들어 있지 않습니다. 대표님의 사진을 넣어 사용하는 빈 틀입니다.

## 어떤 문제를 해결하나요?

- 음식 설명 아래에 엉뚱한 공간 사진이 들어가는 경우
- 사진 다섯 장이 본문 끝에 몰리는 경우
- 파일 이름만 보고 사진 내용을 추측하는 경우
- 첨부했다고 했지만 편집기에 사진이 없거나 중복으로 들어가는 경우

사진팩은 AI가 **실제 이미지 확인 → 문맥별 선택 → 위치 지정 → 결과 확인**을 따르도록 합니다.
AI 모델과 연결 도구에 따라 수행 범위가 달라지며, 문서만으로 업로드 성공을 보장하지 않습니다.

## 직접 파일로 시작하려면

1. `photos` 폴더에 가게 사진을 넣으세요. 이름을 바꾸거나 사진별 설명을 미리 적을 필요는 없습니다. 하위 폴더도 괜찮습니다.
2. 기존 가게 언어팩을 사용하는 AI에게 이 폴더를 연결하고 `PHOTO_PACK.md`를 읽게 하세요.
3. 아래 요청문을 보내세요.

```text
기존 가게 언어팩에 PHOTO_PACK.md를 추가 적용해 줘.
photos 폴더의 실제 사진을 읽고 이번 글의 문맥에 맞게 골라 배치해 줘.
사진 목록과 배치표는 네가 만들고, 내가 확인할 사항만 물어봐.
처음에는 사진 사용 권리를 묶음으로 확인해 줘.
업로드를 할 수 없다면 실제 파일명과 바로 앞 문장으로 넣을 위치를 알려줘.
게시 여부는 기존에 내가 승인한 범위를 따라.
```

이번 글이 아직 없다면 주제 한 줄이나 초안을 함께 주세요.

## 폴더 연결이 안 되는 AI라면

`PHOTO_PACK.md`와 사진 ZIP을 첨부하세요. AI가 ZIP 속 실제 이미지를 열지 못하면
사진을 직접 첨부하거나 여러 묶음으로 나누어 전달합니다.
컴퓨터 폴더 경로만 적었다고 AI가 읽을 수 있는 것은 아닙니다.
새 대화에서 이전 파일이 보이지 않으면 다시 연결하거나 첨부해야 합니다.

## 다음 글부터

새 사진이 생기면 `photos`에 추가하고 이렇게 요청하세요.

> 이번 주제로 글을 쓰고 사진팩을 적용해 줘. 최근 사용 사진도 확인해서 골라 줘.

처음 한 번 AI가 사진 목록을 만들고, 이후에는 추가·변경된 사진을 살핍니다.
같은 파일명을 덮어쓴 사진도 새 내용인지 확인하도록 지침에 포함했습니다.

## 받아야 할 결과

- **공개용 글:** 사진 안내표나 검수 메모가 섞이지 않은 본문.
- **사진 배치표:** 실제 파일명, 보이는 내용, 넣을 소제목과 바로 앞 문장.
- **발행용 사진 묶음:** 파일 생성이 가능한 환경에서만 번호 붙은 사본.
- **확인 결과:** 원고 준비 / 편집기 삽입 확인 / 공개 게시 확인 중 어디까지 했는지.

직접 올릴 때는 배치표대로 사진을 넣으세요.
브라우저 조작 도구가 연결된 AI는 승인된 범위에서 업로드할 수 있지만,
이 문서만 첨부한다고 로그인·파일 첨부 기능이 생기지는 않습니다.

### 배치표 예시

아래 파일명과 문장은 설명용 예시입니다. 실제 결과에는 대표님 사진과 원고가 들어갑니다.

| 사진 | 실제 내용 | 넣을 위치 |
|---|---|---|
| `매장/IMG_1024.jpg` | 골목에서 보이는 가게 입구 | ‘찾아오는 길’의 “골목 안쪽으로 들어오면 입구가 보입니다.” 다음 |
| `메뉴/IMG_1050.jpg` | 메뉴명이 확인된 음식 접시 | 해당 메뉴의 구성 설명 다음 |
| `공간/IMG_1081.jpg` | 창가 테이블 | ‘자리 안내’의 창가 자리 설명 다음 |

**맞는 사진이 3장뿐이면 3장이라고 알려야 합니다.** 무관한 사진이나 같은 사진으로 5장을 채우지 않습니다.

## 내 AI에서는 어디까지 되나요?

| 환경 | 사용 방식 |
|---|---|
| 이미지 첨부 가능한 ChatGPT·Claude 등 | 사진을 읽고 배치표 작성. 대표님이 편집기에 직접 첨부 |
| 로컬 폴더 열람 도구가 연결된 AI | 폴더의 사진 선택과 기록. 파일 생성 가능 시 순서별 사본 준비 |
| Aside 등 브라우저 조작 도구가 연결된 AI | 지원되는 첨부 기능과 로그인 상태를 확인한 뒤 승인된 범위에서 업로드·검증 |

제품 이름만으로 기능을 판단하지 말고 현재 연결된 도구로 실제 이미지가 열리는지 확인하세요.
ZIP을 읽어 파일명만 보여 주는 것과 사진 내용까지 보는 것은 다릅니다.

## 잘못 배치됐다면

> 사진팩 기준으로 다시 확인해 줘. 잘못된 사진과 앞뒤 문단을 비교하고,
> 사진 선택이 틀린 건지 업로드 위치가 틀린 건지 구분해서 그 부분만 고쳐 줘.

사진이 없다는 이유로 관련 없는 사진을 넣거나 같은 사진을 복제해 장수를 채우면 안 됩니다.
사진 원본은 유지하며, 촬영 일시를 오늘로 바꾸지 않습니다.
